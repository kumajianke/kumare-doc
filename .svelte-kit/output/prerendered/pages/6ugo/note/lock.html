锁的类型

乐观锁

介绍

乐观锁假设多个事务/请求在大多数情况下不会发生冲突。它不会在读取时加锁，而是在提交更新时通过版本号（version）或时间戳等机制检测是否有其他操作修改了同一条数据。如果检测到冲突，则当前操作会被回退并提示重试。

优点：读多写少场景下性能优异，不阻塞其他读操作。

缺点：写冲突频繁时需要反复重试，反而增大开销。

悲观锁

介绍

悲观锁假设并发冲突一定会发生，因此在操作资源之前就先获取排他锁。只有持有锁的事务才能读写该资源，其他事务必须等待锁释放后才能继续。典型实现包括数据库的 SELECT ... FOR UPDATE、分布式互斥锁等。

优点：保证了强一致性，适用于写冲突频繁的场景。

缺点：锁等待可能导致吞吐量下降甚至死锁，需谨慎管理锁的粒度和超时。

租约锁

介绍

租约锁（Lease Lock）是一种带有过期时间的分布式锁。持有者在获得锁时会被授予一段固定的租期（Lease），在租期内拥有对资源的独占访问权。租期到达后，锁将自动释放，防止因持有者崩溃或网络中断导致锁永远无法释放（死锁）。持有者可以在租期到期前主动续期（Renew）以延长使用时间。

优点：自带过期保护，避免死锁；适合分布式场景下的资源独占控制。

缺点：需要额外的续期机制来防止正常操作中锁意外过期。

[WIP] Domain 权限认证与授权 — 租约锁

核心机制

在 Domain 层的权限认证与授权流程中，项目使用租约锁来保证同一时间只有一个会话可以执行敏感的权限校验与变更操作，避免并发请求导致的权限状态不一致。

                        ▼
              WebSocket 通道建立
              ┌─────────────────────┐
              │  心跳续期 / 主动释放  │
              └─────────────────────┘
null

加锁

  • 当用户访问需要权限认证的 API 时，系统会自动为该操作获取租约锁
  • 默认锁定时长为 3 分钟（180 秒）
  • 若锁已被其他会话持有，当前请求将等待或被拒绝

续期与过期

通过 WebSocket 长连接实现锁的生命周期管理：

操作说明
续期（Renew）客户端通过 WebSocket 发送续期指令，重置锁的过期倒计时至 3 分钟，确保长时间操作不会因锁超时而中断
释放（Release）操作完成后，客户端通过 WebSocket 主动释放锁，立即让出资源给其他等待的请求
自动过期（Expire）若客户端未续期且超过 3 分钟，锁将自动过期释放，防止因客户端异常（断网、崩溃等）导致锁无法释放
为什么使用 WebSocket？

传统 HTTP 请求是无状态的短连接，无法维持锁的持续续期。WebSocket 提供了双向长连接通道，使得：

  1. 客户端可以周期性地发送心跳来续期锁
  2. 服务端可以在锁过期时主动通知客户端
  3. 连接断开时服务端能立即感知并清理锁资源
