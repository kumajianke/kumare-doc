# 6ugo 机制部分

## 1. 圈子热点机制
### 1.1 机制介绍
:::info[什么是热点机制]
本模块负责处理和更新社区的热度分数。当用户执行特定操作（如浏览或加入社区）时，系统会为目标社区累加不同的热度值。底层依赖 Redis 的有序集合（Sorted Set）进行热度榜单的维护，并使用键值对缓存来限制单个用户的频繁操作（1小时冷却期）~
:::

本模块负责处理和更新社区的热度分数（Hot Value）。当用户执行特定操作（如浏览或加入社区）时，系统会为目标社区累加不同的热度值。底层依赖 Redis 的有序集合（Sorted Set）进行热度榜单的维护，并使用键值对缓存来限制单个用户的频繁操作（1 小时冷却期防刷机制）。

## 1\. 枚举类型 (Enums)

### UserAction

定义了能够触发热度增加的用户行为类型。

| 枚举键名 | 字符串值 | 描述 |
| :---- | :---- | :---- |
| view\_comm | "view" | 用户浏览社区 |
| join\_comm | "join" | 用户加入社区 |

## 2\. 核心函数 (Functions)

### 2.1 add\_hot\_to\_comm\_by\_user\_action

根据用户的具体行为，为指定的社区增加热度，并附带防刷机制。

**参数说明：**

* cid (number): 目标社区的唯一 ID。  
* `userid` (number): 执行操作的用户 ID。  
* action (UserAction): 用户执行的具体操作（枚举值）。

**业务逻辑：**

1. **频率限制（防刷机制）**：查询 Redis 中 hot\_value:user\_done:`{userid}` 的键是否存在。如果存在，说明该用户近期已经触发过热度增加，直接返回 403 错误拦截操作。  
2. **热度分配**：  
   * 如果 action 是加入社区 (join\_comm)，则为该社区增加 **40** 点热度。  
   * 如果 action 是浏览社区 (view\_comm)，则为该社区增加 **20** 点热度。  
3. **状态锁定**：操作完成后，在 Redis 中写入用户的锁定键，设置过期时间（EX）为 **3600 秒**（1 小时）。  
4. **返回结果**：处理成功后返回状态码 200。

**返回值：**

返回一个 APIResponse 对象。

* **成功**：APIResponse(200, "ok", null, null)  
* **失败（触发冷却）**：APIResponse(403, "user done the action on nealy time", null, null)

### 2.2 add\_hot\_to\_comm

底层处理函数，直接与 Redis 交互，更新社区的总热度。

**参数说明：**

* cid (number): 目标社区的唯一 ID。  
* hot\_value (number): 需要增加的热度分数。

**业务逻辑：**

* 调用 Redis 的 ZINCRBY 命令。  
* 在名为 hot\_value:comm 的有序集合（Sorted Set）中，找到成员 cid:`{cid}`。  
* 将其分数（score）累加上传入的 hot\_value。  
* *(注：该方法内部 catch 捕获了异常但不抛出，确保 Redis 操作失败时不会阻断主线程运行)*。
